# Авторизация: bearer-токен

Все операции API NN Agent, кроме проверки состояния, требуют bearer-токен в заголовке `Authorization`.

```bash
curl https://api.nexifyneo.com/v2/client \
  -H "Authorization: Bearer YOUR_API_TOKEN"
```

## Где взять токен

Токен выпускается на клиента и выдаётся при подключении к API через официальный бот [`@nn_official_bot`](https://t.me/NN_official_bot?start=nn_agent_landing). Отдельной формы на сайте нет: бот — единственная дверь и в кабинет, и в доступ к API.

Токен привязан к учётной записи, поэтому в версии `v2` идентификатор клиента не передаётся в пути: сервис определяет клиента по токену.

## Что вернётся без токена

Запрос без заголовка отклоняется с кодом `401`:

```json
{
  "error": { "code": "unauthorized", "message": "Missing bearer token" },
  "request_id": "f04e847d-8505-4b7b-a5c8-7aee42a8fc55"
}
```

Просроченный или неверный токен отклоняется тем же кодом `401` с другим сообщением:

```json
{
  "error": { "code": "unauthorized", "message": "Invalid or expired token" },
  "request_id": "3c254bf0-21bf-44ff-9469-56b8a34d4239"
}
```

Разбор поля `request_id` и остальных кодов — на странице [Ошибки](./errors.md).

## Проверьте доступ одним запросом

```bash
curl https://api.nexifyneo.com/v2/client \
  -H "Authorization: Bearer YOUR_API_TOKEN"
```

Ответ `200` означает, что токен принят и привязан к вашей учётной записи. Ответ `401` — токен не передан или недействителен.

## Предупреждение сертификата

Хост `api.nexifyneo.com` отдаёт самоподписанный TLS-сертификат, поэтому клиенты со строгой проверкой прерывают соединение до того, как дойдёт очередь до токена. Если запрос падает на проверке сертификата, а не на `401`, дело не в авторизации — см. [Известные ограничения](./overview.md).
